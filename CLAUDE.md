# photo-slap — Architecture Notes

Retro-styled Electron photo/video slideshow app by Eddy Sant, built with AI assistance. Modernized July 2026 (Electron 43, React 19, Vite 8, ESLint 9 flat config).

## Process model

Standard three-part Electron app built with `vite-plugin-electron`:

| Part | Source | Output | Notes |
|---|---|---|---|
| Main | `electron/main.ts` | `dist-electron/main.js` | ESM (`"type": "module"`), window + menu + protocol + all IPC handlers |
| Preload | `electron/preload.ts` | `dist-electron/preload.mjs` | `contextBridge` exposes `window.api` only |
| Renderer | `src/` | `dist/` | React 19, no direct Node access (`contextIsolation: true`, `nodeIntegration: false`) |

`npm run dev` runs Vite; the electron plugin builds main/preload in watch mode and launches Electron pointed at the dev server. `npm run build` = `tsc && vite build && electron-builder`.

**Vite 8 uses Rolldown**: bundler options for the main process live under `build.rolldownOptions` (NOT `rollupOptions` — those are silently ignored). `sharp` (native) and `heic-decode` (WASM) are externalized there and shipped via explicit `files` globs + `asarUnpack` in `electron-builder.json5`.

## The media:// protocol

Local media is served through a privileged custom scheme (`protocol.handle('media', ...)` in `electron/main.ts`) instead of `file://` — `webSecurity` stays enabled.

- URL shape: `media://local/<encoded absolute path>`, built by `src/utils.ts:getFileUrl`. The `local` host is a required placeholder: standard-scheme URLs swallow (and lowercase) the first path segment as a host if you omit it.
- **Allowlist**: only files under directories the user opened (folder picker, CLI arg, drag-drop) are served; anything else gets 403. Lives in `electron/pathAccess.ts` (`allowRoot` / `isAllowedPath` / `assertAllowedPath`), which is also the guard for **every** file-touching IPC handler — not just the protocol. Paths are `resolve()`d before comparison so `../` cannot escape, matching is case-insensitive on macOS/Windows, and a sibling directory sharing a root's name prefix does not match.
- Scheme privileges include `supportFetchAPI` + `corsEnabled`, and every response carries `Access-Control-Allow-Origin: *` — without both, `fetch()` from the renderer/worker fails with "Failed to fetch" even though `<img>`/`<video>` tags work.
- **HEIC/HEIF**: Chromium can't decode them, and prebuilt sharp binaries can't either (HEVC is patent-encumbered — sharp only ships AVIF). So `heic-decode` (WASM libheif/libde265) decodes to raw RGBA and sharp encodes JPEG.
- **Display-sized variants** (`?w=<maxDim>`): the renderer never paints full-resolution originals — a 48MP photo is a ~200MB GPU texture, and several alive at once during a transition caused texture thrash (visible artifacts mid-star-wipe). Slideshow requests `?w=4096`, blurred smart background `?w=1600`, grid thumbnails `?w=512` (`getDisplayUrl` in `src/utils.ts`). sharp downscales (and bakes EXIF rotation); GIFs are excluded (animation), PNGs stay PNG (alpha). All derived images (transcodes + downscales) are **cached on disk** (`userData/image-cache`, keyed by path+mtime+size+dim, LRU-capped at 500MB). The LRU sweep runs at startup *and* every 50MB written — a photo-frame install runs for weeks, so a startup-only sweep let the cache grow unbounded for the whole session. Derived responses are sent `Cache-Control: no-cache`: the URL is only path + `?w=`, so a time-based cache kept serving a stale render after a file was edited in place; the disk cache (which does key on mtime) makes the re-derive cheap. The preloader calls `img.decode()` so incoming slides are pixel-ready before the wipe starts.
- **Byte ranges**: `Range` requests get real 206 responses (`fs.createReadStream` + `Readable.toWeb`), and full responses advertise `Accept-Ranges: bytes`, so `<video>` seeking doesn't re-download the file.

## Renderer sandboxing

`contextIsolation: true` / `nodeIntegration: false` are only half of it — the preload exposes `window.api` to *whatever document* ends up in that renderer, so the window is pinned to the app's own page:

- **CSP** is set as a response header from `applyContentSecurityPolicy()` in `electron/main.ts`, not a `<meta>` tag, so the packaged app gets `default-src 'none'` + `script-src 'self'` while the Vite dev server still gets the inline preamble and websocket HMR needs. `style-src` must keep `'unsafe-inline'` (React `style={{…}}` attributes are inline styles).
- **Navigation guards**: `will-navigate` and `setWindowOpenHandler` send anything that isn't the app's own page to the real browser via `shell.openExternal` instead of loading it in a privileged renderer. `setPermissionRequestHandler` denies camera/mic/geolocation outright.
- **Fonts are self-hosted** — Silkscreen (the retro UI face, `@font-face` in `index.html`) *and* Inter (the `body` font, in `src/index.css`). Google Fonts was a launch-time network dependency on an app meant to run offline as a photo frame, and it would have forced two external origins into the CSP. **Both** matter: 1.6.0 self-hosted only Silkscreen and left Inter as a Google `@import`, which the CSP then blocked, so every non-Silkscreen surface silently fell back to `system-ui`. Nothing caught it until `test:smoke` existed. Any new external resource needs either bundling or an explicit CSP entry.

## Launch options

- `photo-slap <directory>` (packaged) or `PHOTO_SLAP_DIR=<dir> npm run dev` — auto-opens that folder (renderer pulls it via `app:getAutoOpen` on mount; pull, not push, to avoid load-order races).
- `PHOTO_SLAP_DEBUG_PORT=<port>` — exposes the Chrome DevTools Protocol; used by `npm run test:e2e`.
- The app is **single-instance** (`requestSingleInstanceLock`); a second launch focuses the running window and, if given a directory argument, pushes its scan to the renderer over `app:openScan`. This also means dev and packaged builds can't run simultaneously.
- Folders can also arrive by **drag-and-drop** (renderer resolves paths via `webUtils.getPathForFile` in the preload — `File.path` no longer exists) or the intro screen's **Resume** button (`lastDirs` in electron-store). All ingestion paths funnel through `ingestScanResult` in App.

## Menus & displays

- `buildApplicationMenu()` in `electron/main.ts` owns the whole menu and is re-run on `screen` `display-added`/`display-removed` so **Window → Send to Display** stays current. `sendToDisplay` moves the window to a display's bounds and fullscreens it (leaving fullscreen first if needed — the macOS transition is animated, hence the `leave-full-screen` wait).
- The **Actions** menu lists every renderer keyboard shortcut using `registerAccelerator: false` (macOS): the key is *displayed* but not registered, so the renderer's keydown handler remains the single owner (registering `Space`/letter accelerators would swallow them from inputs). Menu clicks dispatch over the `menu:action` channel.
- **Menu items must mean the same thing as the keys they display.** The culling items used to dispatch `next` and `delete`, so the item labelled "Culling: Reject to Trash" *trashed the file* while the `X` key it claimed to mirror only recorded a sidecar decision. They now dispatch `culling-keep` / `culling-reject`, and `tests/menuActions.test.ts` asserts every menu item has a renderer handler and that only one item (`Move File to Trash`) is destructive.
- True AirPlay initiation is impossible from Electron; the supported flow is macOS Screen Mirroring (extended display) + Send to Display, documented in the README.

## IPC channels (all defined in `electron/main.ts`, typed in `src/vite-env.d.ts`)

Every handler that touches a path runs it through `assertAllowedPath` / `assertAllowedPaths` / `filterAllowedPaths` first (`filter*` for batch stat lookups, where a stale path is expected and shouldn't fail the whole request). `file:move` allowlists its destination via `allowRoot`, since quick-move targets are chosen in Settings rather than opened as library roots.

| Channel | Direction | Purpose |
|---|---|---|
| `dialog:openDirectory` | invoke | Folder picker (multi-select) → recursive scan → `{ paths, files, errors }` |
| `app:getAutoOpen` | invoke | Scan the CLI/env-provided directory, if any |
| `dir:scan` | invoke | Scan an arbitrary directory (drag-and-drop, Resume) and allowlist it |
| `files:getDates` | invoke | Date-taken per path: EXIF `DateTimeOriginal` from the first 256 KB, mtime fallback (16-way concurrent) |
| `app:openScan` | main → renderer | Scan result pushed from a second app launch |
| `file:delete` | invoke | Move file to Trash (`shell.trashItem`) |
| `file:move` | invoke | Quick-move to a target folder (rename, EXDEV copy+unlink fallback; refuses to overwrite) |
| `power:setBlocked` | invoke | `powerSaveBlocker` on/off — renderer keeps the display awake while playing |
| `file:showInFolder` | invoke | Reveal in Finder/Explorer |
| `file:getExif` | invoke | Read EXIF via `exifreader` → flattened `ExifData` or `null` |
| `store:get` / `store:set` | invoke | Settings persistence (`electron-store`) |
| `dialog:pickDirectory` | invoke | Folder picker without scanning (dedupe-from-start-screen); allowlists the dir |
| `dedupe:scan:exact` | invoke | Exact dupes across a *list* of roots: fast-glob → group by size → SHA-256, 8-way concurrent (videos optional) |
| `dedupe:scan:files` | invoke | Lists image or video paths across roots (perceptual hashing happens renderer-side) |
| `files:getInfo` | invoke | Size/mtime per path, for the dedupe compare cards |
| `library:health` | invoke | Scan roots for corrupt/tiny/unsupported/undated media and orphaned sidecar entries |
| `library:health:repair` | invoke | Remove orphan sidecar metadata or quarantine selected corrupt files under `.photo-slap-quarantine` |
| `library:health:export` | invoke | Save a health report as quoted CSV via the native Save dialog |
| `quarantine:list` | invoke | List manifest-backed and legacy files under each root's hidden quarantine tree |
| `quarantine:restore` | invoke | Restore known quarantine entries without overwriting destination collisions |
| `quarantine:delete` | invoke | Permanently delete selected, validated quarantine entries |
| `quarantine:export` | invoke | Save the current quarantine manifest as CSV |
| `menu:open-directory`, `menu:show-in-finder`, `menu:open-settings` | main → renderer | App menu items (Cmd+O / Cmd+Shift+O / Cmd+,) forward to renderer handlers |
| `menu:action` | main → renderer | Actions-menu items AND phone-remote actions (next/prev/toggle-play/grid/frame/favorite/tags/seek/reveal/delete) dispatch to the same handlers as the keyboard shortcuts |
| `remote:setEnabled` | invoke | Start/stop the LAN remote server; returns the tokenized URL |
| `remote:status` | renderer → main | Playback status pushed for the remote page's polling |
| `remote:library` | renderer → main | The playable list, mirrored so the remote can offer a browse grid |
| `remote:queue` | main → renderer | A guest picked a slide by index; it jumps the queue |

## Renderer structure

- `App.tsx` — slideshow state (file list, index, playback), viewer, video controls. Scan results from any source (dialog, drag-drop, resume, CLI, second instance) go through `ingestScanResult`, which only sets `allFiles`; a single reactive effect derives the playable `files` list from `allFiles` + mediaFilter + sortOrder + shuffle, so persisted settings hydrating after launch re-sort automatically.
- **Date sort**: lazily fetches `files:getDates` the first time a date sort is active (toast: "Reading photo dates…"), cached in a ref until another folder is opened. Name sort runs first so it's the tiebreaker.
- `hooks/usePersistedState.ts` — `useState` that hydrates from electron-store on mount and persists on set; all settings use it.
- `hooks/useLibraryMeta.ts` — favorites/tags/ratings/culling, sidecar load + debounced save. Every mutation goes through it, so a save can't be forgotten. Mutations compute the next value from a `stateRef` mirror and then set it, rather than doing work inside a setState updater (StrictMode double-invokes those). Exports pure `pruneMetadata` / `toggleTag` for testing.
- `hooks/useSlideshowPlayback.ts` — owns "the show must keep moving": the image interval **and** the video stall watchdog (see below).
- `hooks/usePendingDeletes.ts` — deferred trash with an undo window (see below).
- `hooks/useRemote.ts` — remote server lifecycle, the status feed, reactions, guest uploads, join QR. The status push is skipped entirely while the remote is off.
- `hooks/useImagePreloader.ts` — insertion-ordered cache of decoded upcoming slides. Advancing one slide used to discard ten `Image` objects and build ten more, nine of them the same URLs.
- `playlist.ts` — `clampIndex` and `survivingNeighbourPath`, the pure position maths behind "deleting keeps your place".
- `components/ZoomPan.tsx` — wheel-zoom toward cursor / drag-pan / double-click toggle for photos. Transform state lives in refs and is written straight to the DOM (no re-render per pointermove); the wheel listener is attached manually to be non-passive. Resets on slide change via `resetKey`; reports `onZoomChange` so App suspends the Ken Burns class while zoomed.
- `components/SettingsMenu.tsx` — the wider, sectioned options side panel (pure props). It exposes named Photo Frame/Party/Culling/TV presets from `settingsPresets.ts`, remains available on the intro screen, and groups controls by task instead of presenting one long list.
- **Culling mode**: persisted setting, forces photos-only paused review when enabled from the UI. The review bar maps `K`/`Enter` and `X` to persistent, non-destructive Keep/Reject decisions, supports 1–5 ratings, and retains the `H` and `1`–`3` favorite/quick-move shortcuts. Decisions and ratings live in `.photo-slap.json`; Trash remains separate.
- **No-repeat shuffle**: `shuffleHistory.ts` orders unseen paths before seen paths and resets only after the eligible set completes. `App` persists history in electron-store keyed by sorted root set + media filter, records a slide as soon as it is displayed, shows cycle progress, and exposes an explicit history reset.
- `components/LibraryHealthModal.tsx` + `electron/libraryHealth.ts` — filterable health report and confirmed repair actions. Main-process workers validate image decoding (including HEIC), video signatures, tiny dimensions/size, embedded capture dates, common unsupported media extensions, and missing paths referenced by merged sidecars. Repairs remove orphan metadata or preserve corrupt files under the root's hidden `.photo-slap-quarantine` tree; reports export as CSV.
- `components/QuarantineManager.tsx` — lists quarantined files with original locations, size, and timestamp. Restore uses the manifest and collision-safe naming, refreshes the open library and health report, permanent delete requires confirmation, and the manifest exports as CSV. Legacy pre-manifest quarantine files are inferred from their relative path.
- `components/GridView.tsx` + `gridFilters.ts` — virtualized grid with composable filename/tag/favorite/health/rating/culling filters and matching batch metadata actions.
- The blurred smart-background video has **no autoPlay attribute**: the playback-sync effect in App is the single owner of play/pause/seek for both videos, so pausing the main video (or toggling smart background while paused) can't leave the blur playing.
- `components/DedupeModal.tsx` — duplicate finder wizard. One **strictness slider**: level 0 = exact (SHA-256 in main), levels 1–3 = perceptual with Hamming thresholds 4/12/20. Image hashing runs in `workers/phashWorker.ts` (module worker: fetch over media:// → `createImageBitmap` → 16×16 OffscreenCanvas → `blockhash-core`); videos (optional) are hashed by a frame sampled ~1s in, on the main thread — the `<video>` element MUST set `crossOrigin='anonymous'` or the canvas is tainted and `getImageData` throws (media:// is cross-origin to the app). Grouping is transitive union-find in `similarity.ts`. Review compares the group's first two files ("keeper" vs challenger); the survivor keeps facing the rest, so groups of any size are fully reviewed. Compare cards show filename/folder/size/dimensions (`files:getInfo` IPC + media load events) with the better side highlighted. Deletions are reported to App via `onFilesDeleted` so the slideshow drops them immediately.
- `components/Toast.tsx` — transient notices (no media found, unreadable folders); state lives in App (`showToast`).
- `transitions.ts` — slide transition variants; see below. `resolveTransition` implements the **Surprise Me** setting, picking a concrete style per slide and never repeating back-to-back. Crucially the pick happens *after* a slide lands, choosing the style for the **next** change: framer-motion reads `variants` when the incoming slide mounts, and `AnimatePresence`'s `mode` must not flip in the same render as the key (the star wipe needs `sync`, everything else `wait` — see `presenceModeFor`).
- **Ambient letterbox** (`hooks/useAmbientColor.ts` + `file:getAmbientColor`): fills the bars around a photo with the photo's own average colour, dimmed to 42% so it reads as a backdrop. Main derives it from the existing 64px variant (so HEIC decoding, the disk cache and the concurrency cap are reused) and a 1x1 resize is then the arithmetic mean; results are memoised by path+mtime in main and by path in the hook. Images only — a video would need a frame grab. Mutually exclusive with the blurred smart background, which fills the same space, so the toggle is hidden while that is on and every preset picks one deliberately.
- **framer-motion does not animate `filter` here.** The CRT transition originally blew out brightness on entry; measured over 53 frames the transform tweened smoothly while `filter` snapped between exactly two values, for both a multi-function string and a lone `brightness()`. `boxShadow` *does* interpolate (verified the same way), so the CRT glow uses that. Don't reach for `filter` in a variant without measuring it first.
- **Keeping the show moving** (`useSlideshowPlayback`): images advance on an interval; videos advance on `onEnded` and loop when paused. `onEnded` is not guaranteed — it never fires for a file Chromium can't decode (HEVC `.mov` straight off an iPhone is the common case), a truncated or corrupt file, or one deleted from disk while queued. That left the slideshow **parked on that slide forever** with `isPlaying` still true. Two defences now: the `<video>` has an `onError` handler that toasts and skips, and a watchdog skips any video that produces no `timeupdate` for 15s (`onTimeUpdate` re-arms it, so long videos are unaffected). Covered end-to-end by the `2-broken.mp4` fixture in `scripts/e2e.mjs`.
- **A stale index is self-healed**: `currentIndex` past the end of a shrunken list meant `files[currentIndex]` was `undefined`, which both killed the advance timer *and* threw while rendering. `currentFile` is now `files[currentIndex] ?? null`, and an effect clamps the index. Emptying `allFiles` also clears `files` — the derive used to bail out early and leave the last deleted photo on screen.

### Slide transitions

Framer-motion **variants** (`enter`/`center`/`exit`) on a keyed `motion.div` inside `AnimatePresence`, with the navigation direction (1/-1) passed as `custom` on BOTH the motion.div and AnimatePresence — the latter is what updates the already-mounted outgoing slide's exit when direction just flipped (baking direction into a plain `exit` prop leaves it one navigation stale). Directional styles (slide/flip/zoom) mirror when going backwards. The slide wrapper is `position: absolute; inset: 0` so slides can stack.

The **star wipe** needs the outgoing slide to stay visible while the incoming slide is revealed through a growing star-shaped `clip-path`:

- `AnimatePresence` uses `mode="sync"` for star (both slides mounted at once) and `mode="wait"` for everything else.
- `starPolygon(scale)` generates the polygon; scale 0 = collapsed point, scale 4 = inner vertices clear the screen corners (corner distance in % space ≈ 70.7; inner vertices sit at ≈ 18.6 × scale).
- The outgoing slide's `exit` keeps it fully visible (opacity drops only after a 0.65 s delay, once covered) and lowers `zIndex`.
- Don't reintroduce an opacity fade on the star variant — it degrades the wipe into a crossfade (the original bug).

- `components/GridView.tsx` — `G` thumbnail grid with filename/favorites/tag filters and a **select mode** for batch favorite/tag/move/delete (handlers live in App: `batchFavorite`/`batchTag`/`batchDelete`/`batchMove`). Rendering is **hand-rolled windowing**: fixed square cells, explicit `grid-template-columns`, spacer rows (`grid-column: 1/-1`) above/below the visible slice, range computed from scrollTop + ResizeObserver-measured viewport.
- **Keyboard help** (`?`, `components/ShortcutsOverlay.tsx`): the shortcut list lives in `src/shortcuts.ts` as data, and `tests/shortcuts.test.tsx` checks every documented key against the cases the App's keydown handler actually implements, so the two can't drift.
- **Photo-frame mode** (`P`, `components/FrameOverlay.tsx`): ambient clock/date overlay plus the photo's date-taken (fetched lazily per slide via `files:getDates`) and tags. `autoPlayOnOpen` setting makes ingest start playing immediately — together they make a login-item photo frame.
- **Phone remote & party mode** (`electron/remoteServer.ts` + `electron/remoteGuard.ts`): token-guarded HTTP server on an OS-assigned port, LAN interface. The token is **24 bytes** (was 4 — 32 bits is enumerable over a LAN), compared with `crypto.timingSafeEqual`, and wrong tokens cost the client a cooldown via `AuthThrottle` so it can't be guessed at request speed. `UploadBudget` caps total guest uploads per session (500 files / 5GB) — the 200MB per-file cap did nothing against a client that simply repeated the request. Filename sanitizing and collision-free naming live in `electron/guestUpload.ts`. Serves an inline mobile page with a live thumbnail (swipe = prev/next), transport buttons, emoji reactions, and guest uploads. `POST /api/action` forwards whitelisted actions through the SAME `menu:action` channel as the Actions menu; `GET /api/status` returns state the renderer pushes over `remote:status` (the status includes `path`/`root` for server-side use but those fields are STRIPPED from client responses); `GET /api/thumb` serves a 512px derive — of whatever slide is current, or of `?i=<index>` for the browse grid; `GET /api/library` returns a capped page of `{i, name, type}` (never a path) and `POST /api/queue` takes an integer index that the renderer plays next, so a client still cannot name a filesystem path; `POST /api/react` forwards a whitelisted emoji to the renderer (`remote:reaction` → floating overlay); `POST /api/upload` (raw body + `name` query param) is extension-whitelisted, 200MB-capped, filename-sanitized, never overwrites, writes only to `<root>/guests`, and announces the file over `remote:uploaded` — the renderer appends it to `allFiles` and uses `pendingPathRef` so the re-derived list keeps the current slide in place. Token rotates per server start.
- **Hooks must return stable objects.** `useLibraryMeta` returns a `useMemo`'d object: a fresh one each render made every consumer callback unstable, which reached the effects owning the keydown handler and the `menu:action` IPC listeners — they tore down and re-registered ~4x/second while a video played (`timeupdate` is the app's highest-frequency render driver). Same reason `usePendingDeletes` and `useRemote` hold their caller's callbacks in refs. `scripts/e2e.mjs` measures this: it counts `keydown` registrations over 5s of real video playback (was 21, now 0) and asserts the clip actually played, so the check can't pass vacuously.
- **Toasts carrying an action are not replaceable.** The Undo affordance lives only in its toast, so a passing status message ("Skipping X — it won't play") arriving inside the window is dropped rather than silently taking Undo away.
- **Viewed-history writes are debounced** (5s, flushed on `beforeunload`). Every slide appends one path, and writing on each meant serialising a library-sized list to electron-store every few seconds for data only read at startup.
- **Large-library performance**: name sorts use a module-level `Intl.Collator` (per-call `localeCompare(…, options)` is ~20x slower); `deriveImage` in main caps sharp concurrency at 4 with a queue and coalesces identical in-flight requests (grid scrolls request hundreds of thumbs at once); the phash worker hashes 256px variants, not originals; `hammingDistance` early-exits above the threshold for the O(n²) grouping pass. Validated against a 5,000-file library: ~1s ingest-to-render, 35ms re-sort, grid opens in 25ms with ~50 DOM cells.
- **Favorites & tags** (`H`/`T`, `components/TagEditor.tsx`): stored in `.photo-slap.json` sidecars WITH the library, managed by `electron/libraryMeta.ts` (`library:load`/`library:save` IPC). Each path is owned by the deepest sidecar dir containing it; loads merge with shallower-wins, saves write entries back to their owning file (so unfavorites don't resurrect). Favorites/tag *edits* deliberately don't re-derive the playable list (refs, not deps) — only the filter toggles do, or a heart press would reset the slide index. Session-only filters (favoritesOnly/tagFilter) are intentionally not persisted.
- **Slide timer bar** (`showSlideTimer`): CSS width animation keyed by `currentIndex`, duration set inline from `slideDuration`.
- **Update check**: `checkForUpdates` in main hits the GitHub Releases API (unsigned builds can't Squirrel-update, so it opens the release page); quiet check 5s after launch in packaged builds, menu item for manual checks. Tag `v*` pushes trigger `.github/workflows/release.yml` (macOS runner → DMG → GitHub Release).
- **Quick-move** (`1`/`2`/`3`): target folders in settings (`quickMoveFolders`), moves via `file:move`, and the moved file leaves the slideshow through the same `handleFilesDeleted` path as deletions.
- **Deleting** (`usePendingDeletes`): the file leaves the slideshow immediately but the actual `shell.trashItem` is held for 7s, which is the only window in which an undo is possible (trashing can't be reversed from the app). The toast carries an **Undo** action. Anything still pending on unmount/`beforeunload` is flushed, so quitting never silently cancels a delete; a file that fails to trash is put back in the list. **`DedupeModal` deliberately does not use this path** — it deletes immediately, because the user has just compared the pair side by side, and a pending window would fight the review's own advance. It reports any file it could not trash on the final screen rather than letting it silently vanish from the review.
- **Deleting keeps your place.** Removal only touches `allFiles` — the derive effect is the single owner of `files` — and pins `survivingNeighbourPath` in `pendingPathRef` first. The pin is consumed **inside `applyFiltersAndSort`**, not by the `[files]` effect: that effect ran on an earlier render, so the derive's `setCurrentIndex(0)` always won and every delete threw the user back to slide 1.
- **Deleting forgets metadata.** `handleFilesDeleted` calls `meta.forget`, which prunes and *persists*. Without it the sidecar kept entries for paths that no longer existed — the app manufacturing exactly the orphans the library-health repair exists to clean up. (Health repair uses `forgetLocally`: it already rewrote the sidecars.)
- **Resume position**: `resumePositions` in electron-store maps a joined folder-set key to the last index; Resume sets `pendingIndexRef`, consumed once the file list lands.
- The window sets `backgroundThrottling: false` — the slideshow may be playing while the window is occluded (Send to Display), and throttled rAF also freezes framer-motion mid-transition (this broke E2E runs when the window opened behind others).

## Gotchas / conventions

- **`fileScanner.ts` owns the list of playable formats.** `SUPPORTED_EXTENSIONS` is exported and `guestUpload.ts` derives its whitelist from it. They had drifted: uploads accepted `.mov`, which `scanDirectory` does not recognise, so a guest's iPhone video joined the running show and then vanished on the next launch with nothing to explain it. `tests/guestUpload.test.ts` asserts the two lists stay equal. (`.mov`/`.mkv` remain genuinely unsupported — `libraryHealth.ts` lists them as such. Adding them means changing all three lists together.)
- **Two kinds of path containment, and they must not be merged.** `pathAccess.isWithin` is case-SENSITIVE and decides which root *owns* a path; callers then take `path.relative()` against it, and a case-insensitive match between `/A/B` and `/a/b/c.jpg` would yield `../../a/b/c.jpg` and corrupt sidecar/quarantine entries. `isAllowedPath` is case-INSENSITIVE on macOS/Windows because the security check only needs a yes/no and the filesystem is. Both live in `pathAccess.ts`; `libraryMeta.ts` and `libraryHealth.ts` import `isWithin` rather than each keeping a copy.
- **An effect must not list state it also replaces.** `DedupeModal`'s compare-card fetch keyed off `fileInfos` while replacing it with a fresh object every run, so a path `files:getInfo` could not stat — a file deleted since the scan — re-triggered the effect forever, measured at ~2,700 IPC calls a second. Requested paths now live in a ref and `fileInfos` is out of the deps.
- **fast-glob is case-sensitive by default.** `dedupe.ts` passes `caseSensitiveMatch: false`; without it the lowercase `**/*.jpg` patterns missed every `IMG_0001.JPG` a camera produces, so the duplicate finder silently ignored files the slideshow was happily showing.
- `MediaFile`, `ExifData`, and `window.api` are ambient types in `src/vite-env.d.ts` — no imports needed in renderer code.
- **Keep setState updaters pure** (no setState inside another updater): StrictMode double-invokes updaters, which made arrow-key navigation skip a slide in dev until fixed.
- `blockhash-core` and `heic-decode` have no bundled types; minimal declarations live in `src/types/blockhash-core.d.ts` and `electron/heic-decode.d.ts`.
- `scanDirectory` skips dotfiles, collects per-directory errors (e.g. macOS `EPERM` on `Photos Library.photoslibrary`) into `errors`, and still returns the partial scan; the renderer surfaces the count in a toast.
- ESLint: flat config in `eslint.config.js`; `react-hooks/set-state-in-effect` is intentionally off (the slideshow resets per-slide state in effects), `no-explicit-any` off for the IPC boundary.
- `npm run build` requires the Electron binary; if `node_modules/electron/dist` is missing (npm `allow-scripts` blocking install scripts), run `node node_modules/electron/install.js`.

## Testing

- `npm test` — Vitest unit tests in `tests/` (scanner, exact dedupe, similarity grouping, star polygon geometry, media URL encoding, path allowlist + traversal, remote token/throttle/upload budget, guest-upload filename sanitizing, playlist position maths, metadata pruning, and two drift guards that read source: shortcuts-vs-handler and menu-items-vs-handlers). Config lives in `vitest.config.ts`, deliberately separate from `vite.config.ts` so the electron plugin doesn't launch during tests.
- `npm run test:smoke` — `scripts/smoke-packaged.mjs` exercises the **shipped** configuration: the built renderer over `file://` with the production CSP, rather than the Vite dev server the e2e uses. Asserts the page loads from `file://`, React mounts, stylesheets apply, **both** bundled fonts resolve, media:// still serves and still 403s, and that the load produced no CSP violations, uncaught exceptions, or error-level console output. `-- --app <path>` points it at a real `.app` so asar packaging is covered too; CI runs it that way in `release.yml` (before publishing) and bare in `ci.yml` under `xvfb-run`. It found a blocked Google Fonts `@import` for Inter on its first run — a regression that had shipped in 1.6.0 and was invisible to every other test.
- `npm run test:e2e` — `scripts/e2e.mjs` generates an image fixture (deterministic mtimes; downloads a sample HEIC when online), seeds the star-wipe setting (user config backed up and restored), launches the real app with `PHOTO_SLAP_DIR` + `PHOTO_SLAP_DEBUG_PORT`, and asserts over CDP: media:// serving + 403 allowlist, HEIC transcode, star-wipe clip-path interpolation, date sorting, zoom/pan, and the full dedupe review flow. It then **relaunches** against a second fixture (the app is single-instance) containing a deliberately corrupt `2-broken.mp4`, to prove the slideshow advances past media it cannot decode, that deleting keeps your place rather than resetting to slide 1, that Undo restores the file without it ever reaching the Trash, and that `?` opens the shortcut list. Not headless; needs the single-instance lock free. Gotcha: the very first slide mounts before settings hydrate, so transition assertions need one warm-up slide change.

## Improvement ideas (not yet done)

1. **Code signing & notarization** — builds are unsigned; Gatekeeper blocks them on other Macs, and it's what blocks true self-installing auto-update (Squirrel requires a signature).
2. **Dedupe review history** — remember skipped/kept pairs so re-scans don't re-ask.
3. **Sidecar conflict handling** — concurrent edits from two machines (synced folders) last-write-wins with no merge.
4. **HEIC health scans decode every file.** `inspectMediaFile` runs a full WASM HEVC decode just to read dimensions, which is slow on a library of thousands. The decode doubles as the corruption check, so a cheaper header/EXIF path would need to keep that guarantee.
5. **`saveLibraryMeta` globs the whole library on every save** to find sidecar dirs, on an 800ms debounce. Fine locally, noticeable on a network volume.
6. **Extracting the slideshow engine** — playback, the stall watchdog and the preloader are hooks now, but `App.tsx` still owns index/direction/video-ref state directly, so those parts have no unit coverage (only e2e).
7. **Symlink escapes** — the allowlist compares resolved paths but does not `realpath`, so a symlink *inside* an opened folder can still point outside it. Low risk (the user opened the folder), but it is the remaining gap in `pathAccess`.
